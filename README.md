# SPROS

Пилот карты локального спроса для Москвы и Московской области.

## Что работает

- Карта OpenStreetMap с Leaflet, категории, поиск, группировка точек, горячие зоны и раскрытие совпадающих координат.
- Создание запросов, поиск похожих в радиусе 800 м, присоединение, один голос на аккаунт, отдельная готовность внести деньги.
- Предложения предпринимателей в ответ на запрос и самостоятельные идеи, изображения, бюджет, сроки, бонусы.
- Сравнение концепций, одна выбранная концепция на запрос, заявки об интересе без платежа.
- Серверный профиль, собственные запросы, поддержка, заявки, история модерации.
- Жалобы без автоматического скрытия, ручная модерация, объединение с дедупликацией голосов, апелляции и решения с причиной.

Все записи этого запуска — демонстрационные, включая тестовые действия пользователей. Это не показатели реальной аудитории. Начальные числовые примеры отделены от голосов в таблице `supports`.

## Технологии

React 19, TypeScript, Next.js App Router API через Vinext, Cloudflare Worker, D1 (SQLite), Drizzle migrations, R2 для изображений. Примитивы интерфейса — Radix/Shadcn, карта — Leaflet. Авторизация на этом размещении — Sign in with ChatGPT.

Это не стандартный Next.js Node-сервер: Vinext собирает совместимые компоненты и route handlers в Worker. Для переноса на другой хост нужно заменить адаптер окружения/БД и авторизации; интерфейс и предметная логика сохраняются.

## Разработка

Требуется Node >=22.13 и pnpm версии из `packageManager`.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm exec tsc --noEmit
node --import ./scripts/sites-env.mjs tests/integration.mjs
```

Последняя команда запускает собранный Worker в изолированном эмуляторе с временными БД и файловым хранилищем. Она не меняет опубликованные данные. Проверяет авторизацию, уникальность голосов, сумму намерений, дубликаты, жалобы, апелляции, слияние, концепции, лимиты и загрузку файлов.

Для обычной локальной разработки используется `pnpm dev`. При работе через управляемую среду Sites применяются её команды и правила запуска предпросмотра. После изменения схемы: `pnpm db:generate`, затем проверка нового SQL. Ранее применённые миграции не редактируются.

## Модератор

Доступ закрыт по умолчанию. В секрет `SPROS_MODERATOR_IDS` в настройках размещения передаются ID назначенных аккаунтов **этого сайта**, через запятую. Текущий пользователь видит свой site-scoped ID в авторизованном `GET /api/profile` → `profile.id`; ID не равен email. Идентификатор перед назначением сверяется с реальным организатором пилота. После изменения среды требуется публикация с новой ревизией окружения. Не назначать первого произвольного посетителя автоматически.

Рабочая очередь: `/moderation`. Для всех решений обязателен текст причины. В текущем запуске оператор ещё не назначен.

## Состав проекта

- `components/spros/` — карта, карточки, формы, профиль и модерация.
- `lib/domain/` — типы, каталог, геометрия, валидация, переходы статусов, явно обозначенные примеры.
- `lib/server/` — серверная идентификация, ограничения, доступ к данным и чтение моделей.
- `app/api/` — проверяемые серверные команды.
- `db/schema.ts`, `drizzle/` — схема и миграции.
- `docs/architecture.md` — сценарии, границы доверия и путь развития.
- `tests/` — проверки логики и собранного API.
